# 開發進度

本文件記錄「個人管理中心 2.0／財務與訂閱中心／遊戲化習慣養成」的開發進度、驗收條件與驗證結果。

## 起始版本與回復方式

- **起始版本**：`main` 分支 commit `d0bb88c`（Pull Request #1 合併後，第一版「每日待辦與習慣」）。
- **資料格式**：第一版為資料版本 1（localStorage `daily-habit:data`，內容為 `todos`、`habits`、`checkins`）。
- **回復方式**：
  - 程式：本次修改以新的 Pull Request 提交，不直接修改 `main`。若合併後要回到第一版，在 GitHub 的該 Pull Request 頁面按「Revert」，或在本機執行 `git revert -m 1 <合併 commit>` 後推送。
  - 資料：第二版第一次開啟時，會把第一版的原始資料另存在 localStorage `daily-habit:before-v1`，再轉換為版本 2；不會刪除舊資料。第一版程式只讀 `daily-habit:data`，若退回第一版，可在第二版「設定」先匯出備份；第一版無法讀取版本 2 的備份（會拒絕而不覆蓋），此時可用瀏覽器開發者工具把 `daily-habit:before-v1` 的內容複製回 `daily-habit:data`。
- **範圍調整**：研究管理、文獻管理、文件知識庫與 AI 問答不在本次範圍；開始前檢查過，專案中沒有這些相關的工作，因此沒有需要停止或保留的成果。

## 階段 1：資料模型 v2、遷移與畫面模組化

### 驗收條件

1. 版本 1 的 localStorage 資料開啟後自動轉為版本 2，任務、習慣、打卡內容不變；原始內容另存在 `daily-habit:before-v1`。
2. 版本 1 的備份檔可以通過驗證並還原（轉換為版本 2）。
3. 比程式新的資料版本或備份會被拒絕，不覆蓋現有資料。
4. 同一習慣同一天的打卡 id 固定（`c_<習慣id>_<YYYYMMDD>`），重複紀錄會合併。
5. 導覽包含今日、任務、習慣、財務、成長、設定六個區域，手機 375px 無橫向捲動。
6. 未登入（本機）模式與帳號資料分開存放（`daily-habit:data` 與 `daily-habit:u:<帳號>:data`）。

### 驗證結果

- 已實測（單元測試，`npm test`，68 項全部通過）：條件 1～4、6（`tests/storage.test.js`、`tests/backup.test.js`）。
- 已實測（瀏覽器，Playwright + Chromium，375px，Asia/Taipei）：
  - 寫入版本 1 資料後重新整理：顯示升級提示與重複打卡合併提示，localStorage 版本為 2、打卡 id 正確、`daily-habit:before-v1` 存在。
  - 六個區域都能切換，沒有 JavaScript 錯誤；375px 寬度無橫向捲動（修正了 fieldset 撐開版面的問題）。
- 尚未驗證：實體手機、Safari／Firefox。
- 已知限制：`scripts/browser-check.cjs` 仍是第一版的流程，將在階段 6 改寫。

## 階段 2：個人管理中心 2.0

### 驗收條件

1. 任務可新增、編輯、完成、取消完成、封存（及取消封存）、刪除（需確認）；欄位含名稱（必填）、備註、截止日期、優先程度、標籤、子任務。
2. 搜尋（名稱、備註、標籤、子任務）、標籤與優先程度篩選、四種排序。
3. 今日、逾期、本週、全部、已完成、已封存視圖；清單與月曆兩種顯示。
4. 重複任務：每天、每週指定星期、每月指定日期；每月沒有該日時可選「改在月底」或「該月跳過」。
5. 重複任務可「只修改這次」或「修改這次及未來」；刪除可選「只刪這次／這次及之後／整個」，已完成的紀錄保留。
6. 逾期的重複任務只列出最近一次未處理的項目，可完成或略過。
7. 習慣支援每天或每週指定星期；今日打卡、取消打卡、補登過去日期；不能為未來、建立日之前、封存期間打卡；同一天只有一筆。
8. 顯示最近七天、月份紀錄、完成率（近 30 天、當月）、目前與最長連續天數；非排定日、建立前、封存期間不算漏打卡。
9. 修改排程只從今天起生效，不改寫過去統計。
10. 每週回顧：任務完成數、習慣完成率、手動筆記，並顯示統計期間與計算方式。
11. 台灣午夜：跨午夜後今日、逾期、重複項目與習慣狀態自動更新；凌晨完成的任務歸屬台灣當天。

### 驗證結果

- 已實測（單元測試 72 項全部通過）：`tests/recurrence.test.js`（每月 31 日月底／跳過、閏年 2/29、跨年、只改這次、這次及未來、刪除之後、逾期規則）、`tests/tasks.test.js`、`tests/habits.test.js`（每週排程、補登規則、完成率、連續、排程歷史、封存期間）、`tests/review.test.js`（台灣週日 23:30／週一 00:30 歸屬、取消完成後不計）。
- 已實測（瀏覽器 `scripts/browser-check.cjs tasks habits review`，82 項全部通過，手機 375px、Asia/Taipei、時間固定 2026-10-20）：條件 1～11 的主要操作流程，包含月曆跨月檢查 11/30、2027/2/28、1/31 的月底規則，以及 23:58→00:01 跨午夜。
- 測試過程發現並修正：重新繪製後 Playwright `check()` 會等待舊元素（改用實際點擊）；檢視用對話框的按鈕改為「關閉」；週次切換按鈕在手機上換行。
- 尚未驗證：實體手機、Safari／Firefox、螢幕報讀器實際朗讀。
- 已知限制：
  - 重複任務錯過多次時，逾期只列最近一次（附錯過次數）；更早的不再列出。
  - 「修改這次及未來」時，未來已個別修改但未完成的項目會改由新規則產生（個別修改不保留）；已完成的保留。
  - 月曆只對今天起顯示重複任務的預定項目；過去只顯示實際處理過的項目。

## 階段 3：財務與訂閱中心

### 驗收條件

1. 收入、支出可新增、編輯、刪除（需確認）；欄位含日期、金額、幣別、分類、帳戶、備註。
2. 依月份、類型、分類、帳戶篩選，並可用文字搜尋（備註、分類、帳戶、金額）。
3. 每月收入、支出、差額依幣別分開顯示；不同幣別不相加。
4. 金額以最小貨幣單位整數儲存（新台幣以元為單位、不可有小數；美元以分為單位）。
5. 分類每月預算：已用、剩餘、超支提示；修改不重複建立。
6. 分類與帳戶可新增、改名、封存；使用中的只能封存，未使用的可刪除；帳戶「記帳累計」標示不是銀行餘額。
7. 訂閱：名稱、金額、幣別、週期（每 N 天／週／月／年）、下次續費日、付款方式、帳戶、狀態；可暫停、取消、封存；有扣款紀錄的不能刪除。
8. 月繳、年繳以原本的日期推算（1/31 → 2/28 → 3/31）；顯示近期續費、每月與全年預估，換算的數字標示「估算」；暫停或取消的不計入。
9. 預估續費與實際交易分開：只有「記錄扣款」或「連結既有交易」才計入支出；同一次續費只能對應一筆交易；找到金額相同、日期相近的既有支出時提示連結。
10. 續費提醒可建立任務（id 固定，不重複建立）；今日頁顯示站內續費提醒。
11. CSV 匯入：欄位對應（自動猜測）、收支判斷方式、預覽（可匯入／可能重複／錯誤）、預設略過重複、確認後才匯入；同一檔案再匯入不會重複。
12. 匯出收支與訂閱 CSV（UTF-8 BOM，Excel 可開啟；防止公式注入）。

### 驗證結果

- 已實測（單元測試 97 項全部通過）：`tests/money.test.js`（0.1 + 0.2、千分位、小數位數、過大金額）、`tests/finance.test.js`（多幣別統計、篩選、預算超支）、`tests/subscriptions.test.js`（月底錨定、閏年年繳、預估換算、記錄扣款不重複、連結既有交易、提醒任務不重複）、`tests/csv.test.js`（BOM、引號、分號、公式注入、日期金額格式、重複偵測、匯出再匯入）。
- 已實測（瀏覽器 `scripts/browser-check.cjs finance`，60 項；全部群組合計 142 項通過，手機 375px）：條件 1～12 的主要操作。
- 測試過程發現並修正：訂閱卡片的操作按鈕在手機上被擠成直排；CSV 欄位標籤重複「（必填）」；重複載入範例資料時固定 id 的預算會重複（改為略過已存在的 id）；篩選欄位不再顯示「選填」。
- 尚未驗證：實際銀行匯出的 CSV 格式（只用自製的 CSV 測試）；Excel／Google 試算表實際開啟匯出檔。
- 已知限制：
  - 不串接銀行，不做匯率換算；記帳累計不是銀行餘額。
  - CSV 只支援逗號、分號、Tab 分隔與 YYYY-MM-DD／YYYY/M/D 日期；不支援 MM/DD/YYYY（避免月日混淆）。
  - 「可能重複」以日期、類型、金額、幣別、備註完全相同判斷；備註不同的同一筆交易不會被偵測為重複。
