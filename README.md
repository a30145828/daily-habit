# daily-habit：每日管理中心

一個放在 GitHub Pages 的個人管理網頁，包含三個互相整合的模組：

1. **個人管理中心 2.0**：任務（標籤、子任務、重複任務、清單與月曆）、習慣（每天或每週指定星期、補登、統計）、每週回顧。
2. **個人財務與訂閱中心**：收支記帳（多幣別、預算、CSV 匯入匯出）、訂閱（續費預估、提醒、避免重複記帳）。
3. **遊戲化習慣養成**：完成任務與習慣獲得經驗值與金幣、等級與角色成長、成就、自訂獎勵商店（可關閉）。

預設是**本機模式**：不需要帳號，資料只存在你的瀏覽器。網站管理者設定好 Supabase 後，使用者可以**登入並雲端同步**，在多台裝置使用。

- 純 HTML、CSS、JavaScript，沒有建置流程、沒有外部 CDN、不需要 AI API。
- 全介面繁體中文；手機（約 375px 寬）與電腦都可操作；支援鍵盤與螢幕報讀器的基本使用。

網頁使用 JavaScript 模組，**不能直接雙擊 `index.html` 開啟**（瀏覽器會阻擋），請用本機伺服器：

```bash
# 在專案資料夾中執行（需要 Python 3；Windows 若指令是 python，請改用 python -m http.server 8000）

```

然後在瀏覽器開啟 <http://localhost:8000/>。

## 使用說明

畫面分成六個區域：手機上在畫面下方，電腦上在上方。

### 今日

- 顯示已逾期、今天到期的任務（今天已完成的會以刪除線留在下方）、今天排定的習慣、7 天內的訂閱續費提醒，以及角色等級與金幣。
- 第一次使用會看到「歡迎使用」，可以新增第一個任務或習慣，或載入範例資料（範例名稱都以「（範例）」開頭，不會自動加入）。

### 任務

- **新增／編輯**：名稱（必填）、備註、截止日期、優先程度（高／中／低）、標籤（用逗號或頓號分隔）、子任務。
- **完成**：勾選前面的方框；再按一次取消完成。**封存**：暫時收起，可在「已封存」找回。**刪除**：會先確認。
- **視圖**：今日、逾期、本週（今天到週日）、全部、已完成、已封存；也可以切換到**月曆**，點日期查看或新增當天的任務。
- **搜尋、篩選與排序**：搜尋名稱、備註、標籤、子任務；依標籤、優先程度篩選；依截止日期、優先程度、建立時間、名稱排序。
- **重複任務**：新增時選「重複」：
  - 每天、每週指定星期、每月指定日期。
  - 每月 29～31 日遇到沒有這一天的月份，可選「改在該月最後一天」或「該月跳過」。
  - 編輯重複任務時可選「只修改這次」或「這次及未來的項目」；刪除時可選「只刪除這次」、「這次及之後」或「整個重複任務」。已完成的過去紀錄一律保留。
  - 錯過多次時，「逾期」只列出最近一次（並顯示錯過次數），可以完成或「略過」。

### 習慣

- 新增時選擇「每天」或「每週指定星期」。
- 按「完成打卡」為今天打卡；「月份紀錄與補登」可以點過去的日期補登或取消。不能為未來、習慣建立之前或封存期間打卡；同一個習慣同一天只會有一筆。
- 每個習慣顯示最近 7 天、目前與最長連續天數、近 30 天完成率；月份紀錄顯示當月完成率。
- **計算方式**：完成率 = 排定日已打卡天數 ÷ 排定日數。非排定日、建立之前、封存期間、未來，以及今天還沒打卡都不計入。修改執行頻率只從今天起生效，過去的統計不會被改寫。
- 封存的習慣保留所有紀錄，不列入今日；可以還原。

### 財務

- **收支**：新增收入或支出（日期、金額、幣別、分類、帳戶、備註）。依月份查看，可篩選類型、分類、帳戶並搜尋。每月收入、支出、差額**依幣別分開顯示**，沒有匯率資料時不會把不同幣別相加。
- **訂閱**：名稱、每期金額、幣別、週期（每 N 天／週／月／年）、下次續費日、付款方式、帳戶、分類。
  - 顯示近期續費、每月與全年預估（年繳、季繳換算成每月時標示「估算」）。暫停或取消的訂閱不計入。
  - 預估續費**不會**計入收支；實際扣款後按「記錄扣款」才會新增一筆支出，並自動推進下次續費日。同一次續費只能記錄一次。
  - 如果這筆扣款已經從 CSV 匯入，「記錄扣款」會找出金額相同、日期相近的支出，讓你「連結」而不是重複記帳。
  - 「建立提醒任務」會在續費前建立一個任務，同一次續費不會重複建立。
- **預算**：為支出分類設定每月預算，顯示已用、剩餘或超支。
- **分類與帳戶**：新增、改名、封存；使用中的只能封存，不能刪除。帳戶的「記帳累計淨額」只是記帳紀錄的加總，**不是已與銀行核對的餘額**（第一版不連結銀行）。
- **匯入匯出**：
  - 匯入收支 CSV：選檔 → 對應欄位（會自動猜測）→ 預覽與檢查（可匯入／可能重複／錯誤）→ 確認。可能重複的資料預設略過；同一個檔案重複匯入不會重複記帳。
  - 匯出收支與訂閱 CSV（UTF-8，可用 Excel 或 Google 試算表開啟）。

### 成長

- **角色成長**：經驗值決定等級（Lv.2 需要 100 點、Lv.3 需要 300 點……），角色會隨等級長大。
- **每週回顧**：顯示統計期間、本週完成的任務數與習慣完成率（附計算方式），可以寫回顧筆記。
- **成就**：首次完成、累積完成、連續達成等，每個只能領一次。
- **獎勵商店**：自訂獎勵與所需金幣，用金幣兌換；兌換可以退回一次。**金幣是遊戲點數，與財務模組的真實金額完全無關。**
- **獎勵紀錄**：每一筆經驗值與金幣變動（獲得、撤銷、成就、兌換、退回）都會留下紀錄。
- **獎勵規則**：
  - 任務依優先程度給予獎勵；習慣打卡（含補登）每天一份。
  - 同一任務、同一天的打卡只給一份。取消完成或取消打卡會撤銷，重新完成會再給回，但加總最多一份，不能反覆領取。
  - 撤銷後金幣可能變成負數：負數或不足時不能兌換，已兌換的不會被收回。
  - 遊戲化可以在「設定」關閉，任務、習慣、財務不受影響；重新開啟時依目前完成狀態補算。

### 設定

- 帳號與雲端同步（登入、註冊、忘記密碼、同步狀態、衝突處理、登出）。
- 每週起始日、主要幣別、遊戲化開關。
- 儲存空間用量（已使用、剩餘、估計上限，以及各類資料佔多少）。
- 完整備份匯出與還原、載入範例資料、清除所有資料。

## 資料保存、備份與復原

### 資料存在哪裡

| 模式 | 資料位置 | 跨裝置 |
| --- | --- | --- |
| 本機模式（未登入） | 這個瀏覽器的大容量儲存區（IndexedDB，位置 `daily-habit:data`） | 否 |
| 已登入 | 這個瀏覽器的帳號快取（`daily-habit:u:<帳號>:data`），並同步到你的 Supabase 帳號 | 是 |

- 資料存在瀏覽器的大容量儲存區（IndexedDB），上限由瀏覽器依裝置剩餘空間決定，通常是幾百 MB 以上。
- 瀏覽器無法使用 IndexedDB 時（少數舊瀏覽器或特殊隱私設定），自動改用基本儲存區（localStorage，約 5 MB，同一個網址下的所有網站共用），功能完全相同。
- 舊版本存在 localStorage 的資料，會在第一次開啟新版時複製到大容量儲存區；**原本的那份原封不動保留**，不會自動刪除。如果搬移後還開著舊版網頁並修改了資料，會採用較新的版本，另一份另存（`daily-habit:legacy-copy-…`），不會刪除。

- 本機模式下，清除瀏覽器資料、使用無痕視窗、換瀏覽器或裝置，資料都可能消失。iPhone Safari 也可能在網站長期未使用時清除資料。
- 登出會清除這台裝置上的帳號快取（雲端資料不受影響）。登出前如果有尚未同步的變更，會先警告。
- 「設定 → 儲存空間」會顯示儲存方式、已使用、剩餘與上限；超過七成時畫面上方會提醒，超過九成時改為錯誤等級的提醒。空間滿了之後新的變更無法保存（畫面會還原並顯示訊息），但已保存的資料不會被刪除。

### 定期備份

- **完整備份**：到「設定 → 匯出完整備份（JSON）」，檔名例如 `daily-habit-backup-2026-10-20.json`。內含任務、習慣、財務、訂閱、遊戲紀錄等全部資料。建議每週一次，存在安全的地方。
- **財務 CSV**：到「財務 → 匯入匯出」，可另外匯出收支與訂閱。
- 備份與 CSV 含有你的個人與財務資料：**不要提交到 GitHub 或放到公開位置**（`.gitignore` 已排除這些檔名）。

### 從備份還原

1. 到「設定 → 從備份還原」，選擇備份檔。
2. 系統會先檢查資料版本、欄位、日期、金額與識別碼，並顯示筆數。**檢查不通過的檔案不會覆蓋任何資料**；比程式新的版本會被拒絕。
3. 檢查通過後按「以此備份還原…」再確認。還原會**完整取代**目前的資料；預設會勾選「還原前先下載目前資料的備份」。
4. 已登入時，還原後的內容會同步到雲端；備份中沒有的資料會在雲端標記刪除。

第一版（資料版本 1）的舊備份也可以還原，會自動轉換成新格式。

### 資料損壞時

如果瀏覽器中的資料無法讀取，網站會顯示「無法讀取已儲存的資料」，**不會自動清空**。你可以：下載原始資料、重新整理、從備份還原，或改用空白資料開始（原始內容會另存在瀏覽器的 `daily-habit:corrupt-…`）。

### 從第一版升級

第一次用新版開啟時，第一版的資料會自動轉換（待辦 → 任務、習慣加上排程、打卡加上固定識別碼）。轉換前的原始資料會另存在 `daily-habit:before-v1`，不會刪除。過去完成的任務與打卡也會補記遊戲化獎勵（只補一次）。回到第一版的方法請見 [`docs/PROGRESS.md`](docs/PROGRESS.md)。

## 設定雲端同步（Supabase）

不設定也能正常使用（本機模式）。想讓自己在多台裝置使用，請依下列步驟建立免費的 Supabase 專案。**全程不需要付費，也不要啟用付費方案。**

### 1. 建立專案

1. 開啟 <https://supabase.com/dashboard>，註冊或登入。
2. 按 **New project**。
3. 填寫：
   - **Organization**：選你的組織（第一次使用會先建立一個，免費方案即可）。
   - **Project name**：例如 `daily-habit`。
   - **Database Password**：按 **Generate a password**。這是**秘密**，請存在密碼管理器，**不要**貼到任何程式或 GitHub。本網站不需要用到它。
   - **Region**：選離你近的，例如 **Northeast Asia (Tokyo)**。
   - 方案：**Free**。
4. 按 **Create new project**，等待約 1～2 分鐘。

### 2. 建立資料表與權限

1. 左側選單按 **SQL Editor** → **New query**。
2. 打開本專案的 [`supabase/migrations/20261020000000_daily_habit_sync.sql`](supabase/migrations/20261020000000_daily_habit_sync.sql)，複製**全部**內容貼上。
3. 按 **Run**，看到 `Success. No rows returned` 即完成（重複執行也沒關係）。
4. （選用）到 **Table Editor** 確認有 `records` 和 `sync_counters` 兩個表，且標示 **RLS enabled**。

### 3. 設定登入方式與網址

1. 左側 **Authentication** → **Sign In / Providers**（舊版介面為 **Providers**）：確認 **Email** 已啟用，**Confirm email** 保持開啟（建議）。
2. **Authentication** → **URL Configuration**：
   - **Site URL**：填你的 GitHub Pages 網址，例如 `https://<你的 GitHub 帳號>.github.io/daily-habit/`。
   - **Redirect URLs** 按 **Add URL**，加入：
     - `https://<你的 GitHub 帳號>.github.io/daily-habit/**`
     - （若要在自己電腦測試）`http://localhost:8000/**`
   - 按 **Save**。這決定驗證信與重設密碼信的連結會回到哪裡。

### 4. 取得公開設定並填入網站

1. 左側 **Project Settings**（齒輪）→ **API Keys**（或 **API** / **Data API**），找到：
   - **Project URL**：例如 `https://abcdxyz.supabase.co`（在 **Data API** 或 **API** 頁）。
   - **anon public** 金鑰（在 **Legacy API Keys** 分頁，`eyJ…` 開頭）。建議使用這個：本專案的同步功能是以這種金鑰實測的。
     新版的 **Publishable key**（`sb_publishable_…`）依 Supabase 文件也能用在瀏覽器，但尚未實測；若使用後無法登入，請改回 anon 金鑰。
2. 在 GitHub 打開本儲存庫的 `js/config.js`，按鉛筆圖示編輯，填入：

   ```js
   export const SUPABASE_URL = 'https://abcdxyz.supabase.co';
   export const SUPABASE_ANON_KEY = '你的 anon public 金鑰';
   ```

3. 按 **Commit changes**（建議提交到新分支並開 Pull Request，確認後再合併到 `main`）。

### 公開設定與秘密資料

| 項目 | 性質 | 放在哪裡 |
| --- | --- | --- |
| Project URL | 公開 | `js/config.js` |
| anon public 金鑰（或 Publishable key） | 公開（每位使用者的瀏覽器都會拿到；資料由 RLS 保護） | `js/config.js` |
| **service_role／Secret key**（`sb_secret_…`） | **秘密**：可以略過所有權限 | 只留在 Supabase 後台。本網站**不需要**，**絕對不要**放進程式、`config.js`、GitHub 或 GitHub Secrets |
| **Database Password** | **秘密** | 只存在你的密碼管理器 |
| JWT Secret | **秘密** | 只留在 Supabase 後台 |

如果秘密資料不小心外流，請到 Supabase 後台重新產生（Project Settings → API Keys／Database → Reset）。

### 5. 驗證

1. 開啟網站 → **設定**，應該看到「帳號與雲端同步」的登入、註冊表單。頁首會顯示「💾 本機模式」。
2. 按 **註冊**，輸入電子郵件與密碼（至少 8 個字元）→ 收信 → 點信中的連結 → 回到網站並顯示「電子郵件驗證完成，已登入」。頁首顯示「☁ 已同步」。
3. 新增一個任務，等幾秒；到 Supabase **Table Editor → records**，應該看到新的資料列。
4. 用另一台裝置或另一個瀏覽器登入同一帳號，應該看到同一個任務。
5. **Authentication → Users** 應該只有你註冊的帳號。

注意：Supabase 內建的寄信服務每小時只能寄少量信件（適合個人使用）。如果收不到信，請檢查垃圾郵件匣，或稍等後按「重新寄送驗證信」。需要大量寄信時，可以在 **Authentication → Emails → SMTP Settings** 設定自己的寄信服務（選用）。

### 同步規則（給想了解細節的人）

- 變更會先存在這台裝置，1 秒後自動上傳；每分鐘以及回到頁面時會下載其他裝置的變更。
- 離線時的變更會排入佇列，恢復連線後自動上傳。失敗會自動重試（5 秒、15 秒、1 分鐘、5 分鐘），也可以按「立即重試」。
- 兩台裝置同時修改同一筆資料時，**不會自動覆蓋**：「設定」會列出衝突，由你選擇「保留這台裝置的版本」或「使用雲端版本」。
- 刪除會同步到其他裝置，舊資料不會重新出現。
- 登入後，如果這台裝置原本有本機資料，「設定」會顯示預覽筆數，由你決定是否匯入帳號；相同的項目不會重複匯入，重試也安全。
- 遊戲化：同一筆獎勵只入帳一次；兩台裝置同時兌換時，雲端會檢查餘額，拒絕超額的兌換並通知你。

## 安裝到主畫面與離線使用

- **安裝**：Chrome、Edge、Android 版 Chrome 會在網址列或選單提供「安裝」；「設定 → 安裝到主畫面與離線使用」在瀏覽器允許時也會出現安裝按鈕。iPhone／iPad 請用 Safari 開啟，按「分享」→「加入主畫面」。
- **離線**：開啟過一次之後，沒有網路也能開啟並使用（網站檔案由 `sw.js` 快取在裝置上）。有網路時一律下載最新版，所以發布新版不需要額外操作。
- **離線 + 已登入**：離線期間的變更會顯示「離線中：N 筆變更待同步」，恢復連線後自動上傳。
- **通知**：目前只有網站內的提醒（今日頁的逾期任務、續費提醒）。**沒有推播通知**，請不要依賴它在固定時間提醒你。
- 安裝與離線功能需要 HTTPS（GitHub Pages 預設就是）或 `localhost`。

## 發布到 GitHub Pages

本網站是純靜態檔案，可以直接從 `main` 分支根目錄發布：

1. 確認要發布的內容已合併到 `main`，且根目錄有 `index.html`、`.nojekyll`。
2. GitHub 儲存庫 → **Settings** → **Pages**。
3. **Build and deployment** → **Source** 選 **Deploy from a branch**。
4. **Branch** 選 `main`、資料夾選 `/ (root)` → **Save**。
5. 約 1～2 分鐘後會顯示網址，通常是 `https://<你的帳號>.github.io/daily-habit/`。之後推送到 `main` 會自動更新。

說明：

- 所有檔案都用相對路徑，在 `/daily-habit/` 子路徑下可以正常運作。
- 雲端同步直接從瀏覽器連線到 Supabase，不需要其他伺服器，所以不必更換部署方式。
- 同一個網址才會看到同一份本機資料；換網址等於換一份新的瀏覽器儲存空間。

## 隱私與安全

- 本機模式下資料不會離開你的瀏覽器。登入後，資料存在你自己的 Supabase 專案，每個帳號只能讀寫自己的資料（資料庫的 Row Level Security）。
- 網站只使用公開的 anon／publishable 金鑰；不使用、也不需要 service_role 金鑰。
- 使用者輸入一律以文字顯示，不會被當成 HTML 執行；匯出的 CSV 會防止試算表公式注入。
- 登入資訊存在瀏覽器的儲存區（IndexedDB；無法使用時為 localStorage，與 Supabase 官方函式庫相同做法）。在共用電腦使用後請登出，登出會一併清除新、舊儲存區中的登入資訊與帳號快取。
- 不要在備註、付款方式等欄位填寫完整卡號、密碼等敏感資料。

## 已知限制

- 推播通知尚未提供：目前只有網站內的提醒（今日頁）。
- 離線快取依賴瀏覽器支援 service worker；iPhone 在主畫面安裝後，系統仍可能在長期未使用時清除網站資料。
- 不串接銀行、不做匯率換算；記帳累計不是銀行餘額。
- 衝突以「整筆資料」為單位選擇，不做欄位合併。
- Supabase 免費專案一段時間沒有使用可能會被暫停，需要到後台按 **Restore** 恢復（資料不會遺失）。
- 第一版的程式無法讀取新版（版本 2）的資料與備份；回退方式見 `docs/PROGRESS.md`。
